Room Control Webhook Room

Per-room child driver. Add one instance per room you want to control. It registers itself with the root driver over a custom ROOM_CONTROL_WEBHOOK binding.

See also: Room Control Webhook documentation bundled with the root driver.

Setup

  1. Add this driver to the room you want to control (or anywhere — the driver queries its room via C4:RoomGetId()).
  2. In Composer's Connections tab, connect its Root Webhook Link to an available Room Link N on the root driver.
  3. Configure source presets and custom buttons in the Properties panel.
  4. Set Accept Control to On to allow the root driver to route requests to this room.

Properties

PropertyDescription
Accept ControlWhen Off, this room stays linked but the root driver will not route commands or preset/button triggers to it.

Source Presets (Preset 1–5)

PropertyDescription
Preset N NameDisplay name used by the root driver's /preset endpoint.
Preset N SourceDevice selector — pick the audio or video source device for this preset. The driver resolves whether it is a Watch or Listen source at activation time.
Presets are reported to the root driver whenever they change. The root API's GET /presets endpoint reflects the current state of all linked room drivers.

Custom Buttons (Button 1–20)

Enter a name in Button N Name to create a dynamic BUTTON_LINK provider binding with that label. Leave blank to remove the binding.

Each named button appears as a BUTTON_LINK provider binding on this driver. Connect it to any Control4 programming event in Composer. When the root driver receives a POST /button request targeting this room and button name/index, it sends DO_PUSH and DO_RELEASE over the binding, firing any attached programming.

Action valueSignals sent
tap (default)DO_PUSH then DO_RELEASE
press / pushDO_PUSH only
releaseDO_RELEASE only
clickDO_PUSH then DO_RELEASE
