Room Control Webhook

Root HTTP server driver. Add one instance to your Control4 project. It owns the HTTP listener, authentication, client limits, and request routing.

See also: Room Control Webhook Room documentation bundled with the room child driver.

Setup

  1. Add Room Control Webhook to your project (any location is fine).
  2. Add one Room Control Webhook Room driver per room you want to control.
  3. In Composer's Connections tab, link each room child's Root Webhook Link to an available Room Link 1–16 binding on this driver.
  4. Set port, password, and other properties below, then enable the driver.

Properties

PropertyDescription
EnabledStart or stop the HTTP listener. Default: On.
HTTP PortTCP port. Default: 5080.
Bind AddressNetwork interface to bind. !all listens on all interfaces.
PasswordOptional shared secret. Empty = no authentication required.
Allow Raw Room CommandsAllow non-catalog room command strings. Leave Off unless needed.
Allowed Client IPsComma-separated IP allowlist. Empty = any client accepted.
Max Concurrent ClientsMaximum simultaneous HTTP connections. Default: 8.
Max Request BytesMaximum request body size. Default: 8192.
Debug ModeWrite verbose messages to the Control4 log.
Linked RoomsRead-only. Counts and names of linked room children that have registered.
Service Status / EndpointRead-only runtime status and listening URL.

Bindings

BindingClassRole
Room Link 1–16ROOM_CONTROL_WEBHOOKProvider side. Connect each room child's consumer binding here.

Authentication

If a password is set, include it with every request except GET /health:

  • Authorization: Bearer <password>
  • HTTP Basic auth — password field must match.
  • X-Control4-Password: <password>
  • X-API-Key: <password>
  • password or token as a query param, form field, or JSON field.

Endpoints

EndpointDescription
GET /healthUnauthenticated. Returns driver version and status.
GET /roomsLinked room children with enabled state, presets, and buttons.
GET /commandsCatalog of available standard room commands.
GET /presetsSource presets from all linked room children.
GET /buttonsCustom buttons from all linked room children.
GET|POST /commandSend a room command.
GET|POST /presetRun a source preset by name or index.
GET|POST /buttonTrigger a custom button by name or index.
Source presets and custom buttons are configured on each linked Room Control Webhook Room driver, not through this HTTP API.

Room Targeting

The room parameter accepts a numeric room ID, room name, comma-separated list, or all. If exactly one linked room is enabled, room may be omitted.

Room Control Webhook

Root HTTP server driver plus linked per-room child drivers for room commands, source presets, and custom buttons.

Architecture

  • Room Control Webhook: add once. It owns the HTTP listener, authentication, client limits, and request routing.
  • Room Control Webhook Room: add one per room. It owns that room's control enable switch, source presets, and custom buttons.
  • Connect each room child Root Webhook Link to an available root Room Link N. The custom control connection class is ROOM_CONTROL_WEBHOOK.
  • Custom buttons are exposed as dynamic BUTTON_LINK provider bindings on the room child driver, so they can be connected to normal Control4 actions/programming.

Root Driver Properties

PropertyDescription
EnabledStart or stop the HTTP listener.
HTTP PortTCP port. Default: 5080.
Bind AddressInterface to bind. !all listens on all interfaces.

Allowed Client IPsComma-separated allowlist. Empty allows all clients.
Max Concurrent Clients / Max Request BytesHTTP server resource limits.

Room Child Properties

PropertyDescription
Accept ControlWhen off, the room stays linked but root routing will not target it.
Preset 1-5 Name / SourceRoom-specific source presets. The source device ID is stored and resolved at runtime as Watch or Listen.
Button 1-20 NameCreates dynamic BUTTON_LINK bindings for custom actions.
Root Link StatusShows whether this room child registered with the root driver.

Authentication

If a root password is set, send it with any request except /health using one of:

  • Authorization: Bearer <password>
  • HTTP Basic auth; password field must match.
  • X-Control4-Password: <password>
  • X-API-Key: <password>
  • password or token query/form/JSON value.

Endpoints
